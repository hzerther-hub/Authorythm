## 3. app/core/db.py —— 防止第二个进程回收正在跑的任务

### 3.1 问题

`init_db()` 启动时无条件执行：

```python
settle_interrupted_tasks(db, now())   # 把所有 processing 标 failed
```

设计前提是「单实例启动，processing 都是上次残留」。但只要有**任何**第二个
进程调用 `init_db()`（pytest、诊断脚本、第二次启动），它就会把另一个实例
正在跑的任务当孤儿收走。

实测时间线：

```text
20:27:35  用户创建 prompt 任务 #13（章节计划）
20:29     pytest 收集/执行到一个测试，init_db() 落在真实库
20:29:15  #13 被标 failed：任务已失去回执
          应用 PID 32336 全程未变
```

### 3.2 修改

新增跨进程独占锁（`app/core/db.py:36`）：

```python
_lock_fd: tuple[str, int] | None = None


def _acquire_db_lock() -> bool:
    """非阻塞地独占本库,返回**当前进程**是否拿到锁。"""
    global _lock_fd
    lock_path = str(config.DB_PATH) + ".lock"
    if _lock_fd is not None and _lock_fd[0] == lock_path:
        return True
    if _lock_fd is not None:
        try:
            os.close(_lock_fd[1])
        except OSError:
            pass
        _lock_fd = None
    try:
        Path(lock_path).parent.mkdir(parents=True, exist_ok=True)
        fd = os.open(lock_path, os.O_RDWR | os.O_CREAT, 0o600)
    except OSError:
        return False
    try:
        if os.name == "nt":
            import msvcrt
            msvcrt.locking(fd, msvcrt.LK_NBLCK, 1)
        else:
            import fcntl
            fcntl.flock(fd, fcntl.LOCK_EX | fcntl.LOCK_NB)
    except OSError:
        os.close(fd)
        return False
    _lock_fd = (lock_path, fd)
    return True
```

`init_db()` 中的调用改为（`app/core/db.py:514`）：

```python
# 恢复中断任务(对齐原版):按"产出是否已落"归位,而不是一律标 failed。
# 只在没有其它实例活着时做 —— 否则第二个进程(测试/脚本/双开)会把
# 正在跑的任务当孤儿收走,见 _acquire_db_lock()。
if _acquire_db_lock():
    settle_interrupted_tasks(db, now())
```

行为：

- 应用启动 → 拿到锁 → 正常回收上次残留（行为不变）。
- 第二个进程（pytest / 诊断脚本 / 双开）→ 拿不到 → **跳过回收**，不误杀。
- 进程退出由内核释放锁；`.lock` 文件残留无害（`data/` 已 gitignore）。
- Windows 用 `msvcrt.locking`，POSIX 用 `flock`。

### 3.3 注意事项

- 锁文件路径是 `str(config.DB_PATH) + ".lock"`，测试 monkeypatch `DB_PATH`
  时会自动放掉旧锁、换新库。
- 没有强制单实例：第二个应用仍可启动，只是不回收。若要做单实例，应另加
  `QLockFile`/命名互斥，不要把锁改成阻塞。

## 4. 测试隔离修复（误杀的直接原因）

### 4.1 tests/test_video_clone.py

`test_asset_tables_have_deleted_at_column` 原来是：

```python
os.environ["YIHAO_DATA_DIR"] = tempfile.mkdtemp()
import importlib
from app.core import db as _db
importlib.reload(_db)
_db.init_db()          # ← 真实库！
```

**为什么无效**：`config` 在 `app.core.db` 首次导入时就已经算好
`DB_PATH`；之后改环境变量不会重算，`reload(db)` 重新 import 的仍是缓存里的
`config`。所以它一直在用户真实库上跑 `init_db()`。

改为：

```python
def test_asset_tables_have_deleted_at_column(tmp_path, monkeypatch):
    from app.core import db as _db

    monkeypatch.setattr(_db.config, "DB_PATH", tmp_path / "asset_schema.sqlite3")
    old = getattr(_db._local, "conn", None)
    if old is not None:
        old.close()
    _db._local.conn = None
    _db.init_db()
    ...
```

## 5. 资产提取（extractor）修复

### 5.1 根因：系统提示词是「带工具」的 Mastra 提示

`workspace/prompts/extractor.md` 写的是：

```text
1. 调用 read_script_for_extraction 读取格式化剧本
...
7. 调用 save_dedup_characters 保存角色
硬约束：只输出工具调用，不要输出规划文本
```

但 `runner` 只是单次 `chat`，**没有工具**。模型于是：

- 要么把 8192 输出预算全烧在 `<think>Let me analyze...</think>` 上，
  `content` 为空 / 只有推理 → `extract_json` 返回 None；
- 要么直接返回 `{"name": "read_script_for_extraction", "arguments": {...}}`
  —— 合法 JSON，但调用方拿不到 `characters/scenes/props`。

另外，原 `extract_assets()` 对已存在的同名资产直接 `continue`，从不写
`episode_characters / episode_scenes / episode_props`，所以即使模型返回了
「周铁城」等已存在角色，本集资产列表仍是空的。

### 5.2 app/agents/runner.py

新增：

```python
_NO_TOOL_HINT = (
    "\n\n【本次运行环境没有工具】不要调用任何工具,也不要输出 "
    '{"name": "...", "arguments": {...}} 形式的工具调用;直接输出最终 JSON。'
)


def _looks_like_tool_call(data) -> bool:
    return (isinstance(data, dict) and set(data) == {"name", "arguments"}
            and isinstance(data.get("name"), str))
```

`run_agent_json()` 新增 `system` / `max_tokens` 参数，并在解析失败时用
`base_system + _NO_TOOL_HINT` 重试；工具调用 JSON 也视为解析失败：

```python
raw = run_agent(..., system=system, max_tokens=max_tokens)
data = extract_json(raw)
if _looks_like_tool_call(data):
    data = None
if data is None:
    base_system = system if system is not None else prompts.load_prompt(agent_type, lang)
    raw = run_agent(..., system=base_system + _NO_TOOL_HINT, max_tokens=max_tokens)
    data = extract_json(raw)
    if _looks_like_tool_call(data):
        data = None
```

## 11. 追加（21:09）：IPv6 连接挂起导致「生成角色」每个卡约 2 分钟

    ...
    _post_with_negative (app\ai\image_client.py:118)
    generate_image (app\ai\image_client.py:441)   # Agnes 提交

  `GET https://apihub.agnes-ai.com/` 2.4 秒返回 200。

### 状态

- 已重启 app：PID 28440 → **33120**，窗口「易好短剧」正常，`.lock` 已建立。
- 旧批量任务 #19 被启动回收标记 failed（预期：它本来就在 IPv6 上空转）。
- 现在重跑「批量文绘」：每个角色约 20 秒提示词 + 10~30 秒生图，
  10 个角色预计 **5~8 分钟**（仍串行，接口不允许并发）。
